四个概念
记住这四个词就够了

            

              
来源从哪里采。比如一个 GitHub 仓库、一个 arXiv 关键词、一个 subreddit。

              
规则采什么。比如仓库的 Releases 和分支提交，或某个关键词的最新论文。

              
匹配条件留下什么。比如必须包含 AI，或排除招聘。第一次用可以先不填。

              
通知提醒什么。规则命中新内容后，通知会出现在右上角“通知”里。

常见问题
先看这里，少走弯路

          

            
为什么创建了来源，采集不到内容？
来源只是“从哪里采”，还需要在平台详情里创建规则。规则决定采什么；没有规则就不会产生内容。

            
GitHub 分支代码怎么采？
在 GitHub 规则里勾选“分支提交 / 代码改动”。分支留空表示默认分支；也可以填 main, dev。系统会采集提交信息、变更文件摘要和 patch 片段。

            
代码改动太多或触发限流怎么办？
默认每轮最多补丁 10 个提交、每个提交 20 个文件、每个文件 2000 字符。触发 403/429 时提交仍会入库，代码改动标记为暂不可用，不会让整次采集失败。

            
为什么通知里没有内容？
通知只对开启了“新内容”通知的规则生成。先检查规则的“通知”开关，再确认内容确实首次入库。

            
高级 JSON 什么时候用？
只有需要 labels、state、分页上限或自定义匹配时才打开“显示高级选项”。常用 GitHub、arXiv、Reddit 任务不需要 JSON。
